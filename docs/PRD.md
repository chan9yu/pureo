# pureo — PRD

> **이 문서가 제품 요구사항의 SSOT다.** 설계 변경 시 이 문서와 `ROADMAP.md`를 갱신한다.

## 1. 문제

증권사 앱은 수익률 숫자를 보여줄 뿐, **내 포트폴리오가 구조적으로 건강한지 해석해주지 않는다.**
개인 투자자는 "특정 테마에 몰려 있는지, 분산이 되어 있는지, 뭐가 위험한지"에 답을 얻지 못하고,
종목 하나하나의 지표(PER·PBR)도 읽을 줄 모른다.

## 2. 타깃 사용자

- 본인 + 증권 앱을 어려워하는 지인에서 시작
- 국내·미국 주식을 함께 들고 있지만 포트폴리오 구조를 점검해본 적 없는 개인 투자자
- 공유 링크("나도 검사받기")를 통해 유입되는 일반 사용자

## 3. 차별화

**수익률을 '보여주는' 앱이 아니라 포트폴리오 구조를 '진단해주는' 앱.**
종목과 비중만 입력하면 시세 데이터 없이 편중·집중·레버리지 같은 구조적 위험을
쉬운 한국어 문장과 시각 요소로 풀어 읽어준다. 거래 기능이 없는 것이 정체성 —
종목 추천 없이 분산 관점만 제시한다. 종목 단위 해석 카드는 진단의 심화 화면.

## 4. 핵심 기능

| #   | 기능                 | 설명                                                                             |
| --- | -------------------- | -------------------------------------------------------------------------------- |
| 1   | 진단 입력            | 종목 검색 자동완성(국내·미국 큐레이션) + 비중 % 입력 + 선택 설문 3문항           |
| 2   | 진단 리포트          | 건강점수, 국가·섹터·테마·통화 노출, 집중도, 레버리지 경고, 포트폴리오 유형,      |
|     |                      | 시나리오 영향도, 룰 기반 쉬운 한국어 코멘트, 디스클레이머                        |
| 3   | 공유 링크            | 리포트마다 `/r/[token]` — 종목명 기본 숨김 + "나도 검사받기" CTA (바이럴 루프)   |
| 4   | 종목 해석 카드       | 회사 소개·가격 흐름·PER/PBR 게이지·용어 풀이 — 리포트에서 종목 클릭 시 심화 진입 |
| 5   | 로그인·보관함 (후속) | Google OAuth + 내 리포트 목록, 익명 리포트 계정 이관                             |
| 6   | 결제 (후속)          | 무료/PRO 경계는 구조만 준비, 실결제는 사업자등록 후 도입                         |

## 5. 비목표 (Non-Goals)

- 실거래 연동, 실시간 시세·호가, 종목 추천
- 뉴스 수집/요약, 알림 푸시, 커뮤니티
- AI 코멘트·PDF·이메일 발송 (백로그 — 룰 기반 문장으로 시작)
- E2E 테스트, 다크모드 (필요해지면 재검토)

## 6. 성공 기준

- 주식을 어려워하는 지인이 설명 없이 진단을 완료하고 리포트를 이해하는가
- 공유 링크를 받은 사람이 "나도 검사받기"로 새 진단을 만드는가
- 모든 마일스톤이 끝날 때마다 배포 가능한 상태를 유지하는가
- 학습 목표 달성: Next.js App Router(RSC·Route Handler·SSR prefetch)와 TanStack Query v5
  (query·mutation·invalidation·낙관적 업데이트)를 실전 코드로 경험

## 7. 기술 결정 요약

- **스택**: Next.js (App Router) + TypeScript strict, TanStack Query v5, Tailwind CSS 4,
  Vitest + MSW, pnpm 11 / Node 24, Vercel 배포
- **아키텍처**: FSD v2.1 미니멀(`app`·`pages`·`shared`)
- **종목 메타데이터**: git으로 관리하는 정적 모듈(500~1,000종목 큐레이션 — 섹터·테마·ETF 여부).
  진단은 비중 기반이라 시세 불필요. 통합 검색도 이 데이터로 동작
- **데이터 원칙**: 외부 API는 Route Handler로 프록시(키 은닉 + 서버 캐시). DB(Neon + Drizzle)에는
  사용자가 만든 데이터(리포트 스냅샷)만. 리포트는 생성 시점 스냅샷 + 버전 태깅으로 불변
- **소유권**: MVP는 비로그인 — httpOnly 익명 쿠키로 리포트 소유, 로그인 도입 시 계정 이관
- **진단 룰**: 순수 함수(규칙 기반, `analysis-v1`) — 이후 LLM 해석으로 교체 가능한 인터페이스
- **무료/PRO 경계**: 응답 직렬화 계층에서 plan별 필드 분리 구조만 선반영, MVP는 전액 무료
- **외부 데이터(종목 카드 전용)**: 미국 Finnhub + Twelve Data, 환율 한국수출입은행
  (무료 티어, provider 인터페이스로 추상화)
